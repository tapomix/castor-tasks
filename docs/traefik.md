# Traefik Tasks

Declare the site networks of the Traefik reverse proxy without editing YAML by hand.

**Namespace:** `tapomix-traefik`

## Concept

On the VPS, each site joins Traefik through its own internal network: Traefik attaches to `traefik-<site>`, and the
site consumes that network as external. A site whose network is not declared refuses to start.

The sites that use Puppeteer reach it through Traefik: on their network only, Traefik carries the alias `puppeteer`.
The other sites cannot resolve that name. The real protection stays the Puppeteer token (`APP_TOKEN`): the alias makes
the users visible in the config, it does not block a site that would call Traefik by its container name.

These networks live in `compose.sites.yaml`, at the root of the Traefik repository. The file is **owned by the tasks**:
they parse it, change the site list, and rewrite it whole, sorted. Never edit it by hand: comments and any other key
would be lost on the next run. The explanations live in the header the tasks write.

```yaml
# compose.sites.yaml
# generated by `castor traefik:site:*`: do not edit by hand
# (explanations...)
services:
  traefik:
    networks:
      bank-net: {}
      coaching-net:
        aliases:
          - puppeteer
networks:
  bank-net:
    internal: true
    name: traefik-bank
  coaching-net:
    internal: true
    name: traefik-coaching
```

On the VPS, Compose loads it through `COMPOSE_FILE` in the Traefik `.env`:

```dotenv
COMPOSE_FILE=compose.yaml:compose.prod.yaml:compose.sites.yaml
```

> [!IMPORTANT]
> `add`, `remove` and `puppeteer` are only enabled in dev (`APP_ENV=dev`): the Traefik config is changed locally, committed and
> pushed, never edited on the VPS. `list` is available everywhere.

## Available Tasks

### `site:add` - Declare a Site

`<site>` is the `CONTAINER_NAME` of the site: the infra template already sets `TRAEFIK_NET=traefik-${CONTAINER_NAME}`
in the site `.env`, so the site joins its network with nothing to change on its side.

**Aliases:** `tapomix-traefik:site:add`, `traefik:site:add`

```bash
castor traefik:site:add <site>
castor traefik:site:add <site> --puppeteer  # the site uses Puppeteer
```

Adds the site to `compose.sites.yaml` (created when missing), then prints the next steps:

1. Review and commit `compose.sites.yaml`, then push
2. On the VPS: `castor service:update` (Traefik is recreated, a short cut for every site)
3. Start the site on the VPS

### `site:puppeteer` - Grant or Revoke Puppeteer

**Aliases:** `tapomix-traefik:site:puppeteer`, `traefik:site:puppeteer`

```bash
castor traefik:site:puppeteer <site>           # grant
castor traefik:site:puppeteer <site> --revoke  # revoke
```

Adds or removes the `puppeteer` alias on the site network, then prints the next steps:

1. Review and commit `compose.sites.yaml`, then push
2. On the VPS: `castor service:update` (Traefik is recreated, a short cut for every site)

The site network itself does not change: the site keeps running, no restart needed.

> [!NOTE]
> Locally, every site shares `traefik-sites`, which carries the alias: a site declared without `--puppeteer` reaches
> Puppeteer locally and fails on the VPS (`puppeteer` does not resolve).

### `site:remove` - Remove a Site

**Aliases:** `tapomix-traefik:site:remove`, `traefik:site:remove`

```bash
castor traefik:site:remove <site>
```

Removes the site from `compose.sites.yaml`, then prints the next steps:

1. On the VPS: stop the site
2. Review and commit `compose.sites.yaml`, then push
3. On the VPS: `castor service:update`
4. On the VPS: `docker network rm traefik-<site>` — Compose never removes a network it no longer declares

### `site:list` - List the Sites

**Aliases:** `tapomix-traefik:site:list`, `traefik:site:list`

```bash
castor traefik:site:list
```

Shows each declared site and whether it reaches Puppeteer: `V` (green) or `X` (red).

## Error Cases

| Error | Cause |
| ----- | ----- |
| `Invalid site name` | The name holds something else than lowercase letters, digits and dashes |
| `Site "<site>" is already declared` | `add` with a site already in the file |
| `Site "<site>" is not declared` | `remove` or `puppeteer` with a site missing from the file |
| `Site "<site>" reaches Puppeteer already` | `puppeteer` on a site that already has the access |
| `Site "<site>" does not reach Puppeteer already` | `puppeteer --revoke` on a site without the access |

The file is left untouched on error.
